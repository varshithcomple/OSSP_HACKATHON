The problem

Simple schedulers run the highest priority task first. That works until it doesn't.

Some tasks never run

Low-priority work can wait forever while new high-priority tasks keep arriving. This is called starvation.

Apps feel slow

Typing and clicking lag when they queue behind heavy background computation.

One task takes over

A CPU-heavy job can keep the processor busy and leave everything else with nothing.

How it works

The scheduler repeats the same four steps, so priorities keep adjusting while the system runs.

  1. Queue

    Every ready task waits in line with a priority score.

  2. Run

    The highest-scoring task gets the CPU for a short time slice.

  3. Check

    Did it finish, wait for input, or use its whole slice?

  4. Update

    Boost, penalize, and age the other tasks. Then start again.
